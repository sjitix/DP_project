In this project I want to analyse whether LLMs are more expensive in some languages more than others, due to using more tokens. Since they are mostly built from English text, the same sentence can need many more tokens in another language, which makes it more expensive. The research question is: does the same text cost more tokens in some languages, and is this linked to the web presence of that language?

I will take one text that exists in over 200 languages, from the FLORES+ dataset (https://github.com/facebookresearch/flores/tree/main/flores200), and count how many tokens each language needs compared to English, using a tokenizer (OpenAI's tiktoken: https://github.com/openai/tiktoken). Then, I will check if languages with a smaller Wikipedia (less web presence) need more tokens, using the number of articles per language from the List of Wikipedias (https://meta.wikimedia.org/wiki/List_of_Wikipedias) and a table of language codes (https://iso639-3.sil.org/code_tables/download_tables), so that I can match the languages between the two sources. I also have the goal of building my own simple tokenizer, based on what I learn from the Hugging Face tutorial (https://huggingface.co/learn/llm-course/chapter6/5), and training it on English text and text from some other language from Wikipedia articles, downloaded through the Wikipedia API (https://www.mediawiki.org/wiki/API:Main_page), to show that a language can be processed with less tokens when the tokenizer learns from more text in that language.

The final output will be an HTML page generated with bokeh, with one interactive chart for each of the three phases: the token cost of every language compared to English, the token cost compared to the size of each language's Wikipedia, and what is the difference in the number of tokens when training the tokenizer with the selected language compared to number of tokens from tokenizer trained on english.
